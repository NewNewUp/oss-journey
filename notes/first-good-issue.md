# Choosing a good first issue that will actually merge

Note: `notes/first-good-issue.md` — one of the debugging notes in this repository.

- Read the repo's merged PRs first: they show the maintainers' bar for tests and scope.
- Issues with recent maintainer comments get reviews; stale issues get silence.
- One behavior per PR, with the test in the same PR — 'fix and tests to follow' means never.
- Respond to review with evidence, fast; review speed is the real merge currency.

Written while the failure was fresh; the pattern outlives the project.
